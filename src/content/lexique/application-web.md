**Une application web est un logiciel qui s'ouvre dans un navigateur, comme un site, mais qui permet d'agir : se connecter, saisir, enregistrer, suivre. Pour une TPE, c'est souvent la bonne façon de remplacer un tableur ou un carnet par un outil partagé.**

## À quoi ça sert ?

Un site vitrine présente. Une application web **fait travailler**. Elle prend en charge une tâche répétitive de l'entreprise : planifier des interventions, suivre des devis, gérer des réservations, tenir un stock, offrir un espace client.

Son avantage principal : rien à installer. Un ordinateur, une tablette ou un téléphone avec un navigateur suffit, ce qui simplifie l'usage sur un chantier, en boutique ou en déplacement. Les données sont centralisées plutôt que dispersées entre des fichiers.

## Comment ça marche (en pratique)

Une application web se compose de plusieurs éléments :

- **Une interface** (le [front-end](/lexique/front-end-et-back-end)) : écrans, formulaires, listes, boutons.
- **Un serveur et une base de données** (le back-end) : ils stockent les informations et appliquent les règles de votre activité.
- **Des comptes et des droits** : chacun voit ce qui le concerne (le patron voit tout, un salarié son planning).
- **Des échanges avec d'autres services** par [API](/lexique/api) : e-mails, paiement, agenda.

Elle est hébergée sur un serveur et accessible par une adresse web, souvent derrière un identifiant. Quand elle est conçue pour un métier précis, on parle d'[application métier](/lexique/application-metier). Quand elle est vendue par abonnement à de nombreux clients, d'un [SaaS](/lexique/saas).

## Exemple concret

Exemple type : une entreprise de plomberie note ses interventions sur un cahier et un calendrier papier. Une application web permet de créer l'intervention depuis un téléphone, d'y joindre des photos, de l'attribuer à un technicien, puis de générer le compte rendu. Le bureau voit la journée en temps réel, sans rappeler les équipes.

## Les erreurs fréquentes

- **Confondre site et application.** Un site de présentation n'a pas besoin des comptes, des droits et des sauvegardes d'une application ; l'inverse n'est pas vrai.
- **Vouloir tout dans la première version.** Commencez par la tâche qui vous fait perdre le plus de temps.
- **Négliger les sauvegardes et la sécurité.** Une application contient des données de travail et parfois de clients ; ce sont des points de vigilance dès le départ.
- **Ignorer la propriété.** Demandez qui détient le code et les données, et comment les récupérer.
- **Oublier la formation.** Un outil non pris en main par l'équipe ne sert pas.

## Questions fréquentes

**Quelle différence entre application web et application mobile ?**
L'application web s'utilise dans le navigateur ; l'application mobile s'installe depuis une boutique d'applications. Une [PWA](/lexique/pwa) se situe entre les deux.

**Une application web fonctionne-t-elle hors connexion ?**
Pas par défaut. Certaines peuvent stocker des données localement et se synchroniser ensuite ; cela doit être prévu dès la conception.

**Faut-il un abonnement ?**
Un service existant se paie souvent à l'abonnement. Une application sur mesure se facture d'abord à la fabrication, puis éventuellement à l'hébergement et à la maintenance. À comparer sur plusieurs années.

**Est-ce réservé aux grandes entreprises ?**
Non. De nombreuses TPE gagnent du temps avec un outil réduit à leurs besoins réels.
