**Un prompt est la consigne que vous donnez à une IA générative. Plus elle est précise (qui vous êtes, ce que vous voulez, pour qui, sous quelle forme), plus la réponse est exploitable ; elle reste un brouillon que vous relisez.**

## À quoi ça sert ?

Le prompt est le point d'entrée de tout outil d'[IA générative](/lexique/ia-generative). Une demande vague donne une réponse vague : « écris un texte pour mon site » produit un texte générique, interchangeable avec celui de n'importe quel concurrent. Une demande précise donne un point de départ réellement utile.

Savoir rédiger une consigne revient à savoir briefer un collaborateur : on explique le contexte, l'objectif, le public, le ton, le format attendu.

## Comment ça marche (en pratique)

Un bon prompt contient en général cinq éléments :

- **Le rôle ou le contexte** : « Je suis plombier chauffagiste dans un village d'Indre-et-Loire. »
- **L'objectif** : « Je veux répondre à un client qui demande pourquoi son devis a augmenté. »
- **Les informations utiles** : les faits à utiliser, que vous fournissez vous-même.
- **Le ton et le public** : « Poli, simple, sans jargon, pour un particulier. »
- **Le format** : « Quatre phrases maximum, sans formule excessive. »

On peut ajouter des **contraintes** (« n'invente aucun chiffre », « dis-moi quand une information manque ») et des **exemples** de ce que vous aimez. Si le résultat ne convient pas, on précise la consigne plutôt que de recommencer à zéro : « raccourcis », « change le ton », « supprime la dernière phrase ».

Deux précautions. D'abord, ne mettez pas dans un prompt des [données personnelles](/lexique/donnee-personnelle) de clients ou des informations confidentielles si les conditions de l'outil ne vous rassurent pas. Ensuite, vérifiez les faits de la réponse : le prompt améliore la forme, il ne garantit pas la vérité.

Dans un [chatbot](/lexique/chatbot) ou un outil intégré, le prompt est parfois rédigé une fois pour toutes par le concepteur, afin de définir son rôle et ses limites. Le visiteur n'en voit rien, mais la qualité du service en dépend.

## Exemple concret

Exemple type : une caviste veut une fiche descriptive pour un vin. Première version : « Décris ce vin. » Résultat générique. Seconde version : « Je suis caviste indépendante. Rédige quatre phrases pour la fiche d'un vin rouge de Touraine dont je te donne les notes de dégustation ci-dessous. Public : amateurs curieux. Ton : chaleureux, sans superlatifs. N'ajoute aucune information absente de mes notes. » Le texte est plus fidèle, plus court, plus utile. Elle le relit encore avant publication.

## Les erreurs fréquentes

- **Demander sans contexte.** L'outil ne connaît ni votre métier, ni votre région, ni vos clients.
- **Ne pas fournir les faits.** Si vous ne les donnez pas, il en invente.
- **Accepter sans relire.**
- **Poser dix questions d'un coup.** Mieux vaut avancer par étapes.
- **Coller des informations sensibles** dans un service dont vous ne maîtrisez pas l'usage des données.
- **Copier un prompt « miracle »** trouvé en ligne sans l'adapter à votre cas.
- **Oublier de conserver ceux qui fonctionnent.** Gardez vos bons prompts dans un document partagé.

## Questions fréquentes

**Faut-il des connaissances techniques pour écrire un prompt ?**
Non. Il s'agit d'écrire clairement ce que vous voulez, comme dans un brief.

**Un long prompt est-il meilleur qu'un court ?**
Pas forcément. Il doit contenir l'essentiel : contexte, objectif, faits, ton, format. Le reste alourdit.

**Peut-on réutiliser un prompt ?**
Oui, c'est même conseillé pour les tâches récurrentes. Adaptez-le à chaque cas et gardez-le dans un document.

**Le prompt garantit-il une réponse exacte ?**
Non. Il améliore la pertinence, mais les faits doivent être vérifiés par vos soins.
