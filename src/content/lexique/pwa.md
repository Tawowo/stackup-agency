**Une PWA (application web progressive) est un site qu'on peut ajouter à l'écran d'accueil de son téléphone et utiliser comme une application, sans passer par une boutique d'applications. Pour une TPE, c'est une alternative plus légère à une application mobile classique.**

## À quoi ça sert ?

Fabriquer, publier et mettre à jour une application mobile native pour chaque système demande un budget et une organisation hors de portée de beaucoup de petites structures. La PWA offre une partie de ses avantages à partir d'un seul site : une icône sur l'écran, un affichage plein écran, un démarrage rapide et, selon le cas, un fonctionnement partiel sans réseau.

Elle est utile quand vos clients ou votre équipe reviennent souvent au même outil : suivi de chantier, carte de fidélité, planning, prise de commande. Pour un site de simple présentation, elle n'apporte généralement rien.

## Comment ça marche (en pratique)

Une PWA est un site classique auquel on ajoute trois ingrédients :

1. **Une connexion sécurisée** : le site doit être servi en [HTTPS](/lexique/https).
2. **Un fichier de description** (le « manifeste ») : nom, icône, couleurs, mode d'affichage.
3. **Un script en arrière-plan** (le « service worker ») : il garde en mémoire certaines pages ou données pour accélérer l'affichage et permettre un usage hors ligne limité.

Le visiteur n'a rien à télécharger depuis une boutique : selon son appareil, le navigateur propose d'ajouter le site à l'écran d'accueil. Le site doit être bien adapté aux petits écrans, ce qui suppose un travail de [responsive design](/lexique/responsive-design).

Les possibilités varient selon le système et le navigateur, et certaines fonctions de téléphone restent mieux gérées par une application native. À vérifier au moment du projet, car cela évolue.

## Exemple concret

Exemple type : un électricien équipe ses techniciens d'un outil de suivi d'interventions. Les techniciens l'installent sur leur téléphone via le navigateur, retrouvent leur planning en un geste et consultent les fiches même quand le réseau est faible en sous-sol. Les mises à jour sont publiées sur le serveur : personne n'a rien à réinstaller.

## Les erreurs fréquentes

- **En vouloir une pour un site vitrine.** Sans usage récurrent, l'icône sur l'écran n'apporte rien.
- **Promettre le hors ligne partout.** Ce qui peut se faire sans réseau doit être défini précisément ; les paiements, par exemple, exigent une connexion.
- **Oublier les différences entre appareils.** Le comportement n'est pas identique partout : testez sur les téléphones réellement utilisés.
- **Négliger la lisibilité sur mobile**, qui reste la base d'une PWA.
- **Compter sur les notifications** sans avoir vérifié ce qui est possible chez vos utilisateurs.

## Questions fréquentes

**Une PWA remplace-t-elle une application mobile ?**
Pour beaucoup d'usages simples, oui. Si vous avez besoin d'un accès poussé aux fonctions du téléphone ou d'une présence dans les boutiques d'applications, une application native reste adaptée.

**Faut-il un compte développeur ou une publication en boutique ?**
Non, la PWA se diffuse par son adresse web.

**Une PWA est-elle bonne pour le référencement ?**
Elle reste un site web, donc indexable. L'important demeure le contenu, la vitesse et la qualité mobile.

**Est-elle plus chère qu'un site ordinaire ?**
Elle demande un travail technique supplémentaire. Le coût dépend de ce qu'elle doit faire ; une estimation passe par un échange sur votre besoin.
