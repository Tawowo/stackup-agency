**Le mobile first signifie concevoir un site d'abord pour le téléphone, puis l'adapter aux écrans plus grands. C'est aussi la règle de Google, qui analyse en priorité la version mobile de vos pages pour les classer.**

## À quoi ça sert ?

Deux raisons expliquent cette approche. La première tient aux usages : pour beaucoup de recherches locales, un client cherche depuis son téléphone, parfois en situation de besoin immédiat (une panne, un restaurant, un horaire). La seconde tient au référencement : Google indexe et évalue la version mobile des pages en priorité. Si votre contenu est plus pauvre sur mobile que sur ordinateur, c'est la version pauvre qui compte.

## Comment ça marche (en pratique)

Concevoir en mobile first oblige à hiérarchiser. L'écran est petit, la connexion parfois lente, l'attention courte. On décide donc de ce qui est indispensable : qui vous êtes, ce que vous faites, comment vous joindre. Le reste vient après.

Les conséquences pratiques sont les suivantes.

- **Un contenu identique sur mobile et sur ordinateur.** Ne masquez pas de textes ou de liens importants sur le téléphone.
- **Des pages légères.** Images optimisées, peu de scripts, polices raisonnables.
- **Des gestes simples.** Menu clair, boutons larges, numéro cliquable.
- **Des fenêtres discrètes.** Évitez les fenêtres qui couvrent l'écran.

Le mobile first prolonge le [responsive design](/lexique/responsive-design) : celui-ci décrit la capacité à s'adapter, l'autre l'ordre dans lequel on conçoit. Pour mesurer l'effet sur la vitesse et la stabilité des pages, on s'appuie sur les [Core Web Vitals](/lexique/core-web-vitals).

## Exemple concret

Exemple type : une fleuriste a un site complet sur ordinateur, mais sa version mobile cache la liste des bouquets et les horaires derrière un long menu. Une cliente cherche depuis son téléphone « fleuriste ouvert dimanche » et ne trouve pas l'information. La fleuriste fait remonter horaires et contact en haut de page mobile et rétablit les textes manquants. Google lit désormais la même information que celle que voit la cliente.

## Les erreurs fréquentes

- **Cacher du contenu sur mobile.** Il risque de ne pas être pris en compte pour le classement.
- **Concevoir sur grand écran puis « réduire ».** Les priorités se perdent en route.
- **Négliger la vitesse mobile.** Une connexion lente rend les pages lourdes pénibles.
- **Des boutons collés les uns aux autres.** Les clics se trompent de cible.
- **Ne jamais tester sur un vrai téléphone.** Un simulateur ne remplace pas un appareil réel.

## Questions fréquentes

**Mobile first, est-ce la même chose que responsive ?**
Non, mais les deux vont ensemble. Le responsive adapte l'affichage ; le mobile first décide de partir du téléphone pour concevoir.

**Google ignore-t-il ma version ordinateur ?**
Il utilise principalement la version mobile pour l'indexation. Elle doit donc contenir l'essentiel de votre contenu.

**Mon site doit-il être différent sur mobile ?**
La présentation oui, le contenu essentiel non. Mêmes textes, mêmes liens, mise en page adaptée.

**Comment vérifier mon site sur mobile ?**
Ouvrez-le sur un téléphone, testez les boutons, la lecture et la vitesse. Les outils de Google, comme la Search Console, signalent aussi les problèmes détectés.
